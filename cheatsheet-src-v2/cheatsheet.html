Ch01–02CPU ทำงานยังไง · Register★ ดู flow ให้ออก

  • CPU = Control Unit + ALU + Registers + Bus
  • วงจร: Fetch → Decode → Execute → Store (Write back)
  • PC เก็บ ตำแหน่งคำสั่งถัดไป
  • IR เก็บคำสั่งที่ fetch มาแล้ว
  • Status/Flag เก็บ overflow, negative
  • MAR = address ใน Memory
  • MBR = data ที่เข้า/ออก Memory
  • IOAR = address ของ I/O
  • IOBR = data ที่รับจาก I/O
★ ตัวอย่างอาจารย์ (assignment)
  • PC = 300 → Mem[300] = 1940 → โหลดเข้า IR
  • 1940: 4 บิตบน = opcode (0001 = Load AC จาก Memory)
  • ที่เหลือ 940 = address ของข้อมูล
  • Mem[940] = 0003 → AC = 0003

Ch01Performance · CPU time · CPI★ ข้อคำนวณ

X เร็วกว่า Y กี่เท่า = TimeY / TimeX
CPU time = IC × CPI × Cycle time
= IC × CPI / Clock rate
Clock rate = 1 / Clock period
  • เทียบ 2 เครื่อง ISA เดียวกัน → ตัด IC ทิ้ง
  • ไม่รู้ค่า IC ให้ติดตัวแปร I ไว้
  • ⚠ "เร็วกว่า" = ใช้เวลาน้อยกว่า
  • อ่านโจทย์ดีๆ ว่าใครหารใคร
ตย. สไลด์ A: cycle 250 ps, CPI 2.0 · B: cycle 500 ps, CPI 1.2
  • A = I × 2.0 × 250 = 500I ps
  • B = I × 1.2 × 500 = 600I ps
  • → A เร็วกว่า 1.2 เท่า
ตย. Clock A: 2 GHz, 10 s · B ต้อง 6 s และใช้ cycles มากกว่า 1.2 เท่า
  • ClockB = 1.2 × (10 × 2×10⁹) / 6 = 4 GHz

Ch02Bus · Arbitration★ Daisy chain = priority

  • Address bus บอกตำแหน่งใน Memory
  • Data bus ส่งข้อมูล
  • Control bus สัญญาณเปิด/ปิด/เลือกอุปกรณ์
  • Point-to-point: แยกทุกหน้าที่ ง่ายสุดแต่ เปลืองเส้น
  • Multipoint: ประหยัด (ไฮเวย์ + ซอย) แต่ต้องมี โปรโตคอลควบคุม
Arbitrationหลักการ
1 Daisy chainตาม priority (CPU > Memory > I/O)
นิยมสุด ใช้ถึงวันนี้
ข้อเสีย: priority ต่ำแทบไม่ได้ใช้ bus

  • ★ ตัวเลือกว่าอุปกรณ์ไหนได้ใช้ bus = Bus Arbitrator

  • InfiniBand = I/O ความเร็วสูงสุด ใช้กับ GPU ↔ memory

Ch02Interrupt★ flow “จำไว้เลย”

★ Interrupt flow
  1. Save register / PC / status ปัจจุบัน
  2. เปิด Interrupt Vector table หา ISR address (เช่น เบอร์ 003 = คีย์บอร์ด)
  3. ใส่ address นั้นใน PC → รัน ISR
  4. Restore ค่าที่ save ไว้ → กลับไปทำงานเดิม
  • Sequential: เกิด → ทำ → กลับ → เกิดอีก → ทำ → กลับ
  • Nested: Y ซ้อนเข้ามาระหว่าง X → save X, ทำ Y, คืนค่า X, ทำ X ต่อ
  • ซ้อนได้กี่ชั้น = จำนวน register ที่เก็บค่าได้

Ch04Associative · Write Policy★ ถูกถาม

  • Set-associative: index เดียวเก็บได้หลายชุด
  • 2-way เก็บ 2 · 4-way เก็บ 4 · 8-way เก็บ 8
  • แค่เพิ่มที่เก็บต่อ index → โอกาส hit มากขึ้น
  • ★ Fully associative = miss น้อยสุด (hit มากสุด)
  • Miss rate: 1-way 10.3% · 2-way 8.6% · 4-way 8.3% · 8-way 8.1%
  • ดีขึ้นแต่ได้น้อยลงเรื่อยๆ
Write policyความหมาย
Write-throughเขียนลง cache แล้วส่ง CPU เลย
Write-backส่ง CPU ก่อน แล้วค่อยอัปเดต cache ทีหลัง
Write-allocateอีกทางเลือกของ write-through
ปัจจุบัน memory เร็วขึ้น กลไกการเขียนหมดความสำคัญ เน้นยัดโค้ดที่ใช้บ่อยเข้า L1 · แต่ต้องรู้ชื่อทั้ง 3 คำ

Ch04คำนวณบิต Tag/Index/Offsetเสริม

Offset = log₂(bytes ต่อ block)
Index = log₂(จำนวน block)
Tag = บิต address − Index − Offset
ตย. 4 KB direct-mapped, 16 B/block, address 32 บิต
  • 4096 / 16 = 256 block
  • Index 8 · Offset 4 · Tag 32 − 8 − 4 = 20
  • ถ้า 2-way: sets = 128 → Index 7 · Tag 21
  • Hit ratio = hits / accesses
  • Miss ratio = 1 − hit ratio
  • Block ใหญ่ขึ้น: miss rate ลด (spatial locality)
  • แต่ cache เท่าเดิมมี block น้อยลง แย่งกันมากขึ้น miss penalty สูงขึ้น → ใหญ่ ≠ ดีเสมอ

Ch07Pipeline · Hazard★ ถามชนิด/วิธีแก้

  • Pipeline = แบ่งงานเป็น stage ใช้ resource ไม่ชนกัน
  • ทำหลายคำสั่งพร้อมกัน → เร็วขึ้น แต่เกิด hazard
  • เปรียบ: ซักผ้า → อบ → รีด → เก็บ
  • Stage: IF → ID → EX → MEM → WB
  • ลำดับที่อาจารย์ย้ำ: Fetch → Decode → Execute → Write back
  • ⚠ ใช้ได้ทั้ง RISC (ARM) และ CISC (Intel) ไม่ใช่เฉพาะ RISC
