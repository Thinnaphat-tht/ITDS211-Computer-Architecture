Ch01Performance · CPU time · CPI★ ข้อคำนวณ

Performance = 1 / Execution time
X เร็วกว่า Y n เท่า: PerfX/PerfY = TimeY/TimeX = n  (ตย. A 10 s, B 15 s → 15/10 = 1.5)
CPU time = Clock cycles × Cycle time = Clock cycles / Clock rate
Clock cycles = IC × CPI ⇒ CPU time = IC × CPI × Cycle time = IC × CPI / Clock rate
  • Clock rate = 1/period (250 ps = 0.25 ns · 4 GHz = 4×10⁹ Hz) · Elapsed time (รวม I/O, OS, idle) ≠ CPU time (user + system)
  • IC ← โปรแกรม/ISA/compiler · CPI ← hardware · CPI เฉลี่ย ← instruction mix († = Σ CPIi × ICi/IC)
ตย. CPI (สไลด์) ISA เดียวกัน A: 250 ps, CPI 2.0 · B: 500 ps, CPI 1.2 → A = I×2.0×250 = 500I ps · B = I×1.2×500 = 600I ps → A เร็วกว่า 1.2 เท่า (IC ตัดทิ้ง ถ้าไม่รู้ค่าติดตัวแปรไว้)
ตย. Clock (สไลด์) A: 2 GHz, 10 s · B ต้องเสร็จใน 6 s แต่ใช้ cycles มากกว่า 1.2 เท่า → Clock rateB = 1.2×(10×2×10⁹)/6 = 4 GHz

Ch02Interrupt★ ขั้นตอน “จำไว้เลย”

  • Interrupt = ขัดจังหวะการทำงานแบบ sequence ของ CPU · ชนิด: Program (overflow, หาร 0, illegal instr) · Timer · I/O (เสร็จ/ขอบริการ/error) · Hardware failure (ไฟดับ, parity) · Hardware vs Software interrupt (system call)
  1. เซฟ context (PC/PSW, register, ตัวแปร) ไว้ก่อน
  2. ดู Interrupt Vector table หา ISR address (ใครเป็นคนเรียก)
  3. ใส่ address นั้นใน PC → กระโดดไปทำ ISR (Interrupt Service Routine)
  4. เสร็จ → Restore ค่าที่เซฟ แล้วกลับไปทำงานเดิมต่อ
  • Sequential: ทำทีละตัวตามลำดับ (เกิด→ทำ→กลับ→เกิดอีก) · Nested: ระหว่าง ISR ของ X มี Y ซ้อน → เซฟสถานะ X → ทำ Y → คืน X → ทำ X ต่อ → return · ซ้อนได้กี่ชั้นขึ้นกับ CPU (จำนวนชุด register ที่เก็บ context)
  • มักปิด interrupt ระหว่างทำ ISR (maskable ปิดได้ · nonmaskable ต้องทำ) · interrupt ต้องรอ instruction cycle จบ

Ch04Cache: Hit/Miss · Direct-Mapped★ อาจารย์ “เน้นเรื่อง Cache”

  • Cache = หน่วยความจำเร็วคั่นกลาง CPU↔Main memory เก็บข้อมูลที่ใช้บ่อย/ซ้ำ · Block (line) = หน่วยที่ copy · Hit = เจอใน cache · Miss = ไม่เจอ → ดึง block จาก main memory มาใส่ cache แล้วส่ง CPU (เวลา = miss penalty) · Hit ratio = hits/accesses · Miss ratio = 1 − hit ratio
Direct-mapped: Cache index = (Block address) modulo (#Blocks in cache) → ใช้ บิตล่าง เป็น index
Address = [ Tag | Index | Block offset ]   offset = log₂(bytes/block) · index = log₂(#blocks) · tag = ที่เหลือ

Ch04AMAT · CPU time กับ memory stall

AMAT = Hit time + Miss rate × Miss penalty
CPU time = (execution cycles + memory stall cycles) × cycle time
Stall cycles = (Mem accesses/Program) × Miss rate × Penalty = (Instr/Program) × (Misses/Instr) × Penalty
ตย. AMAT clock 1 ns, hit 1 cycle, penalty 20 cycles, miss 5% → 1 + 0.05×20 = 2 ns  ·  ตย. CPI base CPI 2, I-miss 2%, D-miss 4%, load/store 36%, penalty 100 → 2 + 0.02×100 + 0.36×0.04×100 = 2 + 2 + 1.44 = 5.44 → ideal เร็วกว่า 5.44/2 = 2.72 เท่า
  • Multilevel: L1 เน้น hit time ต่ำ · L2 เน้น miss rate ต่ำ · block L1 < block L2 · ตย. CPI = 1 + 0.02×20 + 0.005×400 = 3.4 (เทียบ 9 ถ้ามี L1 อย่างเดียว → 2.6 เท่า)

Ch04ท้ายบท: Dependability · Virtual Memoryอยู่ในสไลด์ (ติวยังไม่ได้พูด)

  • Dependability: Reliability = MTTF · ซ่อม = MTTR · MTBF = MTTF + MTTR · Availability = MTTF/(MTTF+MTTR) (เพิ่มโดย ↑MTTF หรือ ↓MTTR)
  • Hamming distance (จำนวนบิตที่ต่าง): 2 = ตรวจ error 1 บิต (parity) · 3 = แก้ 1 บิต + ตรวจ 2 บิต · parity bit อยู่ตำแหน่งกำลังของ 2 · SEC/DEC (distance 4) · ECC DRAM = 8 บิต ต่อทุก 64 บิต
  • Virtual memory: main memory = “cache” ของ disk · virtual → physical · block = page (≈4 KB) · miss = page fault (ช้ามาก, OS จัดการ) · page table (index ด้วย virtual page no.; มี physical page no. + referenced/dirty bit) · fully associative · write-back เท่านั้น · TLB = cache ของ page table (16–512 PTE, hit 0.5–1 cycle, miss rate 0.01–1%)
  • Cache coherence (หลาย core): snooping (ดัก bus; invalidate ก่อนเขียน) vs directory-based · Virtual machine: host/VMM จำลอง guest OS
