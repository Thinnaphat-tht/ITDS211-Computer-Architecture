  • แนวคิด (ซักผ้า–อบ–รีด–เก็บ): แบ่งงานเป็น stage ย่อย เหลื่อมกันทำ ใช้ resource คนละตัวพร้อมกัน → throughput ↑ แต่ latency ต่อคำสั่งเท่าเดิม · stage ต่างกันตามชนิด CPU (RISC-V / Arm / Intel)
  • ⚠ Pipeline ใช้ได้ทั้ง RISC (เช่น ARM) และ CISC (เช่น Intel) ไม่ใช่เฉพาะ RISC · ลำดับ: Fetch → Decode → Execute → Write back

  • Single-cycle Tc = 800 ps (ตามคำสั่งช้าสุด) · Pipelined Tc = 200 ps (ตาม stage ช้าสุด) · speedup อุดมคติ ≈ จำนวน stage (ซักผ้า 4 โหลด = 8/3.5 = 2.3 · ไม่หยุด = 2n/(0.5n+1.5) ≈ 4)
  • ตย. † ld 3 คำสั่งติดกัน: single-cycle = 3×800 = 2400 ps · pipelined = (5 stage + 3 − 1) × 200 = 1400 ps (n คำสั่ง k stage = (n + k − 1) × Tc)
  • ISA เหมาะ pipeline: ทุกคำสั่ง 32 บิต (x86 = 1–17 byte) · format น้อยและสม่ำเสมอ · load/store addressing
  • Pipeline registers (IF/ID · ID/EX · EX/MEM · MEM/WB) เก็บข้อมูลจาก stage ก่อนหน้า ไม่ให้ถูกคำสั่งถัดไปทับ (hardware เพิ่ม = ต้นทุน) · สรุป: pipeline เพิ่ม throughput ไม่ใช่ latency

Controlคำสั่งก่อนหน้าเป็น branch/jump → คำสั่งที่ fetch ไว้ ไม่ถูกใช้Stall/bubble จน pipeline กลับปกติ (ส่วนใหญ่นิยม เพราะ prediction ต้นทุนวงจรสูง) · Branch prediction (เดา: static = backward taken, forward not taken · dynamic = เก็บ history ต่อ branch; ผิด → flush) · ย้าย target adder+comparator ไป ID
  • Load-use hazard: ผลจาก ld ได้ที่ MEM — forward ย้อนเวลาไม่ได้ → stall 1 cycle · ตย. code scheduling (a=b+e; c=b+f): 13 cycles → จัดใหม่ (ย้าย load x4 ขึ้น) = 11 cycles
  • Forwarding (รายละเอียดจากสไลด์): EX hazard เมื่อ EX/MEM.Rd = ID/EX.Rs1/Rs2 · MEM hazard เมื่อ MEM/WB.Rd = Rs1/Rs2 · เฉพาะ RegWrite และ Rd ≠ x0 · mux ForwardA/B: 00 = register file · 10 = EX/MEM · 01 = MEM/WB
