  • เมื่อเกิด interrupt: เก็บ PC + status register (PSW) ลง stack → PC ← จุดเริ่ม ISR → รัน ISR → return: คืน PC เดิม + คืนค่าใน stack ทั้งหมด แล้วทำงานเดิมต่อ · ปัญหาออกแบบ 2 ข้อ: ใครเป็นคน interrupt? · ถ้ามีหลายตัวทำตัวไหนก่อน?
Device identificationหลักการ
1 Multiple interrupt linesแยกเส้น interrupt คนละเส้น รู้ทันทีว่าใคร · ข้อเสีย: I/O เยอะ เส้นเยอะ
2 Software pollกระโดดไป routine ที่ไล่ถามทีละ I/O module ว่าใครเรียก · ช้า
3 Daisy chain(hardware poll, vectored) priority · interrupt acknowledge ส่งต่อเป็นลูกโซ่ · vector = address/ID ของ module
4 Bus arbitration(vectored) module ต้องขอคุม bus ก่อน จึงยก interrupt request · ได้รับตอบแล้วส่ง vector ผ่านสาย data/address
  • ต่อ I/O เยอะ: ตัวเลือก 8-to-1 (mux) เลือกได้ทีละ 1 · I/O 64 ตัว = 8 ชุด 8-to-1 + อีก 1 ตัวเลือกจาก 8 กลุ่ม (master/slave interrupt controller, ตย. 82C59A)
