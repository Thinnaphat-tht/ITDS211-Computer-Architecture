ทดสอบความเข้าใจ

ทำข้อสอบจากเนื้อหาในไฟล์นี้ ตอบแล้วเฉลยทันที พร้อมลิงก์กลับไปอ่านทวน

จุดที่อาจารย์พูดเกี่ยวกับข้อสอบ แยกเป็นหมวด (รวมจากทั้ง 5 คลิป)

กดที่ป้าย "คลิป n" เพื่อกระโดดไปหัวข้อต้นทาง · หมวด 1–4 เป็นสิ่งที่อาจารย์พูด หมวด 5–6 มีส่วนที่ผมสรุปเอง (ระบุไว้ในข้อ)

1) รูปแบบและกติกาการสอบ

  • ข้อสอบเป็น multiple choice 60 ข้อ (นักศึกษาถาม อาจารย์ตอบ "ใช่เลยครับ") คลิป 4
  • เอากระดาษเข้าห้องสอบได้ 2 แผ่น A4 · ปริ้นต์ได้ ไม่ต้องเขียนมือก็ได้ คลิป 5
  • เปิดสไลด์ในห้องสอบไม่ได้ คลิป 5
  • อาจารย์จะ "แกล้งสัก 2–3 ข้อ" นอกนั้น ทุกอย่างอยู่ในสไลด์ และอาจอยู่ใน assignment คลิป 1

2) เน้น — อาจารย์พูดชัดว่าจะออก / ให้จำ / ให้ดูดี ๆ

  • คำนวณ Sign-Magnitude และ 2's Complement: "จะมีข้อนี้แน่ๆ บอกไว้เลย" ต้องทำให้ได้เต็ม (เหมือนใน assignment) คลิป 1
  • ขั้นตอนเมื่อเกิด Interrupt (เซฟค่า → ดู Interrupt Vector หา ISR → ใส่ PC กระโดดไปทำ → restore แล้วกลับ): อาจารย์บอก "จำไว้เลย" คลิป 1
  • CPI และสูตร CPU time (Instruction count × CPI × Cycle time): อาจารย์ย้ำให้ "ดูดีๆ" คลิป 1
  • Ch04: จำรูปพีระมิดหน่วยความจำ และ เน้นเรื่อง Cache (hit/miss, direct-mapped, tag/index/valid bit, set-associative) คลิป 2
  • Ch06 Storage: ออกไม่เยอะ แต่ตรงไปที่ Hard disk หลักการเขียน/อ่านและการทำงาน คลิป 4
  • ตอนปิดคลิป 4 หลังไล่ Ch05–08 จบ: "ท้ายสุดน่าจะเป็นประมาณนี้ ที่อาจารย์จะออกในข้อสอบ" คลิป 4
  • ปิดคลาสในคลิป 5: "คำถามสไตล์ประมาณแบบเนี้ย ไปทบทวนเนาะ" (โจทย์สั้น 15 ข้อ พร้อมคำตอบ อยู่ในคลิป 5) คลิป 5

3) ระดับพื้นฐาน / ไม่ยาก — อาจารย์บอกว่าง่าย

  • Ch01 องค์ประกอบคอมพิวเตอร์และ CPU: "basic มากๆ" คลิป 1
  • Register PC / IR / Status: "ไม่น่ามีประเด็น" คลิป 1
  • เปรียบเทียบ Performance (เท่าตัว): "บัญญัติไตรยางศ์ง่ายๆ เป็นเรื่อง relative ธรรมดา" ให้อ่านโจทย์ดี ๆ ว่าเร็วกว่า = ใช้เวลาน้อยกว่า คลิป 1
  • Assembly: เป็นช้อยส์ ต้องเข้าใจแค่ว่าคำสั่งทำอะไร (ADD, LOAD, STORE, ADDI, beq/bne/blt/bge, AND/OR/XOR, shift) ไม่ต้องเขียนโค้ด คลิป 1 คลิป 2
  • Procedure / software interrupt: ส่วนที่เหลือของ Assembly "ไม่น่ามีอะไร" คลิป 2
  • Ch05 คำถามจาก assignment (USB vs SCSI, Thunderbolt, InfiniBand ใช้กับอะไร): แนวทั่วไป "basic ไม่ยากมาก" คลิป 4

4) ไม่ออก / ไม่ต้องลงลึก

  • ส่วน self study เฉพาะ RISC-V ที่อาจารย์ทิ้งไว้ให้อ่านเอง: "ไม่ได้ออกข้อสอบ" คลิป 2
  • ไม่เจาะจงตระกูล RISC-V / MIPS / ARM: เป็นความรู้ทั่วไป ไม่ต้องท่องคำสั่งเฉพาะตระกูล คลิป 1
  • ไม่ต้องเขียนโค้ด Assembly (ข้อสอบเป็นช้อยส์) คลิป 1
  • MISD: อาจารย์บอกว่า "ไม่มีเลยแล้ว" (เป็นข้อเท็จจริง ไม่ได้บอกว่าไม่ออกสอบ) คลิป 4

5) อาจารย์พูดถึง แต่ไม่ได้บอกว่าออกหรือไม่ออก

  • Write-through / Write-back / Write-allocation: อาจารย์เล่าเป็นประวัติว่างานวิจัยลดลงเพราะ memory เร็วขึ้น แต่ในคลิป 5 อาจารย์ก็ถามชื่อทั้งสามแบบ (ควรรู้นิยาม) คลิป 2 คลิป 5
  • Ch03 (Data Representation / Floating point): อาจารย์ถามเรื่อง IEEE 754 exponent (single 8 บิต / double 11 บิต) ในคลิป 5 พอนักศึกษาถามว่า "ถามบท 3 เยอะ แปลว่าออกเยอะไหม" อาจารย์ตอบหยอกว่า "จำข้อสอบไม่ได้แล้ว" คลิป 5
  • Ch07 Pipeline และ Ch08 Parallel/GPU: อาจารย์ไล่สอนในคลาสติว แต่ไม่ได้ระบุเป็นหัวข้อเน้นเอง (ผมไม่ทราบว่าอยู่ในขอบเขตสอบหรือไม่ ให้เช็คกับประกาศ/อาจารย์) คลิป 4
  • Hazard 3 แบบ, Flynn's taxonomy, RAID: อธิบายละเอียดในคลิป 4 ไม่มีคำบอกระดับความสำคัญ คลิป 4 คลิป 4 คลิป 4

6) หัวข้อในสไลด์ที่ "ไม่พบ" ในซับของคลิป (ผมสรุปเอง)

เท่าที่ซับถอดได้ ไม่พบคำพูดถึง: Virtual memory / Page table / TLB, Hamming code (SEC/DED), Cache coherence, Dependability (MTTF/MTTR), MARIE (Ch02 หน้า 17–27) และรายละเอียดเชิงลึกของ Floating point

"ไม่พบในซับ" ไม่เท่ากับ "ไม่ออก" ซับขาดบางช่วง (คลิป 2 ช่วง 25:00–26:51 อาจารย์เปิดสไลด์ Dependability Measures อยู่ แต่ไม่มีเสียงที่ถอดได้) ถ้าห่วงหัวข้อไหนเป็นพิเศษ ให้ถามอาจารย์หรือยึดตามประกาศ

ข้อจำกัดของสรุปนี้:
  • ทำจากซับที่ Gemini ถอดเสียง ไม่ใช่การฟังเสียงโดยตรง อาจมีคำผิด ผมเทียบศัพท์และตัวเลขกับสไลด์ในหลายจุด
  • คลิป 2 ไม่มีซับ ช่วง 25:00–26:51 · คลิป 3 ซับถึง 10:58 · คลิป 4 เวลาในซับเพี้ยนหลายนาที ผมใช้เวลาจากสไลด์ที่เห็นในวิดีโอแทน
  • ข้อความที่เป็น "คำพูดอาจารย์" เขียนตามที่ซับถอดได้ ส่วนที่ผมเสริมจากสไลด์ติดป้ายบอกไว้ในหมายเหตุของหัวข้อนั้น

ขั้นตอนการทำงานของ CPU (Machine Cycle)

  • อาจารย์พูดเสมอว่า CPU ทำงานเป็น "สเต็ป" (3 หรือ 5 สเต็ปแล้วแต่รุ่น/แบรนด์) แต่หลัก ๆ หนีไม่พ้น:
    1. Fetch ดึงคำสั่ง
    2. Decode ถอดรหัสว่าต้องทำอะไร แล้วเตรียมข้อมูล
    3. Execute ประมวลผล (บวก ลบ คูณ หาร)
    4. Store เก็บผลลัพธ์ลง Register หรือ Memory
  • บางที่เรียกขั้นสุดท้ายว่า Write back ขึ้นกับประเภท/แบรนด์ของ CPU
02:10

Register สำคัญใน CPU

  • PC (Program Counter) เก็บ ตำแหน่ง ของคำสั่งที่จะประมวลผลถัดไป
  • IR (Instruction Register) เก็บ คำสั่งที่ Fetch มาแล้ว
  • กลุ่ม Status / Flag register เก็บสถานะ เช่น Overflow, Negative flag
  • อาจารย์บอกว่าส่วนนี้ "ไม่น่ามีประเด็น"
02:44

ลำดับชั้นหน่วยความจำ (Pyramid) และ Cache

Clock, CPU time และ CPI

  • Clock frequency (speed) = 1 ÷ Clock period (คาบ)
  • CPU time หาได้จาก CPU clock cycles ÷ clock rate
  • CPI = Clock cycles per Instruction (อาจารย์ให้ "ดูดีๆ")
  • CPU time = Instruction count × CPI × Cycle time เมื่อเทียบสองเครื่อง ตัวแปร Instruction count ตัดทิ้งได้ (ถ้าไม่รู้ค่าก็ติดตัวแปรไว้ก่อน) แล้วหารกันเพื่อดูว่าเร็วกว่ากี่เท่า
CPU time = Instruction count × CPI × Cycle time
Frequency = 1 / Clock period
ตัวอย่างบนสไลด์ (CPI Example): A: cycle 250 ps, CPI 2.0 · B: cycle 500 ps, CPI 1.2 · ISA เดียวกัน
CPU time A = I × 2.0 × 250 = 500·I ps, CPU time B = I × 1.2 × 500 = 600·I ps → A เร็วกว่า 1.2 เท่า

Bus: Point-to-point vs Multipoint

  • Point-to-point: แยกทุกหน้าที่ออกจากกัน ง่ายสุดแต่ เปลืองเส้น (Data ชุดหนึ่ง Address ชุดหนึ่ง Control ชุดหนึ่ง)
  • Multipoint: ประหยัดเส้น เหมือน ถนนไฮเวย์ (เส้นหลัก) + ถนนซอย ที่แยกไปหา CPU/Memory/Disk/I/O แต่การสื่อสารซับซ้อนขึ้น จึงต้องมี โปรโตคอลควบคุม

Sequential vs Nested Interrupt

  • Sequential: Interrupt เกิด → ไปทำ → กลับมา → เกิดอีกครั้ง → ไปทำ → กลับมา ตามลำดับ
  • Nested interrupt: ระหว่างทำ service routine ของ Interrupt X มี Interrupt Y ซ้อนเข้ามา → ต้อง เซฟสถานะของ X ก่อนไปทำ Y เสร็จแล้ว คืนค่าของ X ทำ X ต่อจนจบ แล้วค่อย return กลับโปรแกรมปกติ
  • ซ้อนได้กี่ชั้นขึ้นกับสถาปัตยกรรม CPU ของแต่ละแบรนด์ ว่ามี Register ให้เซฟค่าจากการ Interrupt กี่ชุด (มี 2 ชุด = ซ้อนได้ 2 ที) ถ้าซ้อนเกินกว่าที่ Register เก็บได้ก็ซ้อนต่อไม่ได้
  • Interrupt คือสิ่งที่ ขัดขวางการทำงานแบบ sequence ของ CPU

  • Miss = ไม่เจอ → ไปเอาข้อมูลจริงจาก main memory มาใส่ cache แล้วค่อยส่งให้ CPU ใช้

เทคโนโลยีหน่วยความจำ: SRAM, DRAM, Flash, Disk

  • SRAM (Static RAM): ใช้ transistor เปิด-ปิด (on-off) แค่ไม่กี่ตัว เร็วกว่า DRAM เกือบ 100 เท่า แต่ราคาแพงกว่า
  • DRAM (Dynamic RAM): transistor น้อยกว่า เก็บข้อมูลเป็น ประจุใน capacitor ต้องคอยชาร์จประจุอยู่ตลอด จึง ช้ากว่า แต่ ถูกกว่า
  • Flash (NOR gate หรือ NAND gate): เก็บ logic 0/1 ด้วย transistor ใช้เป็น storage ทั่วไป
  • Hard disk: จุได้เยอะกว่า flash เขียนข้อมูลด้วย magnetic (ไปดูรายละเอียดอีกครั้งในบท storage)

Direct-Mapped Cache: หลักการ

  • cache มีหลักการหลัก ๆ 2–3 แบบ แบบแรกที่ง่ายสุดคือ direct-mapped
  • ตำแหน่งใน cache = block address modulo จำนวนบล็อกใน cache
  • ตัวอย่าง: cache 8 บล็อก (index 000–111) → เอา block address mod 8 ก็คือดู 3 บิตล่าง เป็น index
  • ข้อดี: ง่าย · ข้อเสีย: ตำแหน่งเดียวกันมีหลายเลขที่อยากเข้ามาอยู่ (เช่น ตำแหน่ง 1 กับ 11 ลงท้าย 1 เหมือนกัน) จึงแย่งกันได้
Cache index = (Block address) modulo (#Blocks in cache)

ตัวอย่าง Direct-Mapped: Tag, Index, Valid bit

  • สไลด์: cache 8 บล็อก, 1 word/block, direct-mapped เริ่มต้น cache ว่างเปล่า (Valid = N)
  • แยก address: ตัวอย่าง 10110 (= ที่ 22): 2 บิตบน = Tag (10) · 3 บิตล่าง = Index (110)
  • ครั้งแรกที่ขอ 22 → Miss แน่นอน (cache ว่าง) → ไปเอาจาก main memory เขียนลง cache ช่อง 110, ตั้ง V = Y, ใส่ tag 10 แล้วส่งข้อมูลให้ CPU
  • ขอ 26 (11010): Miss เหมือนกัน → เก็บที่ index 010, tag 11
  • ขอ 22 และ 26 อีกครั้ง → มีข้อมูลแล้ว จึง Hit ไม่ต้องไป main memory
  • ขอ 16 (10 000) Miss, 3 (00 011) Miss, ขอ 16 ซ้ำ = Hit
  • ขอ 18 (10 010): index 010 มีข้อมูลเดิมอยู่ แต่ tag ไม่ตรง (เดิม 11 ใหม่ 10) → Miss แล้วเขียนทับ
  • วิธีเช็กว่า hit หรือ miss: ดู Index → เทียบ Tag → ดูว่า V (Valid) เป็น Y หรือไม่
  • ถ้ามี index (บล็อก) เยอะ โอกาสเจอ (hit) ก็มากขึ้น

  • ขั้นที่ 2: Block number = 75 modulo 64 = 11

Write policy: Write-through / Write-back / Write-allocation

  • เมื่อ miss ต้องไปเอาข้อมูลจาก main memory เขียนลง cache แล้วส่งให้ CPU:
    • Write-through: เขียนลง cache แล้ว ส่งให้ CPU เลย (ตามคำอธิบายของอาจารย์)
    • Write-back: ส่งข้อมูลให้ CPU ก่อน แล้วค่อย อัปเดตบล็อกใน cache ทีหลัง
    • Write-allocation: อีกทางเลือกหนึ่งของ write-through
  • เรื่องเล่าของอาจารย์: เมื่อ 10 กว่าปีก่อนมีงานวิจัย (paper) แข่งกันเรื่องกลไกการเขียนค่าเยอะมาก เพราะ cache สมัยนั้นยังไม่เร็ว แต่ ปัจจุบัน transistor เล็กลงเหลือระดับ 2–4 นาโนเมตร memory เร็วและจุได้มากขึ้น เรื่องความเร็วไม่ใช่ปัญหาหนัก algorithm การเขียนค่าเหล่านี้จึงค่อย ๆ หายไป เพราะ "ลงทุนทำเยอะ แต่ improvement ไม่มีนัยสำคัญ"
  • ปัจจุบันเน้นแค่ ยัดโค้ดที่ execute บ่อยๆ เข้า cache L1 ให้ได้เยอะที่สุด ทุกอย่างก็ hit และ performance ดีขึ้น

Cache อีก 2 ชนิด: Set-Associative และ Fully-Associative

  • นอกจาก direct-mapped ยังมี set-associative กับ fully-associative
  • แทนที่จะให้ index 0 เก็บได้ 1 ชุด ก็ให้เก็บได้หลายชุดเป็น set:
    • 2-way เก็บ 2 · 4-way เก็บ 4 · 8-way เก็บ 8 · 16-way เก็บ 16
  • อาจารย์สรุปว่า "ไม่ได้ฉลาดอะไรมากขึ้น" แค่ ขยายจำนวนที่เก็บใน index เดียวกัน เพื่อเพิ่มความน่าจะเป็นของการ hit

บทที่ 5: ระบบ I/O

I/O และ External Device

  • I/O = Input / Output ใช้ buffer เก็บข้อมูลที่ผ่านเข้า-ออก
  • ข้อมูลอาจเป็น digital หรือ analog ขึ้นกับว่าส่งผ่านทางสายหรืออากาศ (ในแผนภาพคือ Transducer ที่แปลงสัญญาณ)
  • ในสไลด์ External Device ประกอบด้วย Control Logic, Buffer, Transducer มีเส้น Control, Status, Data
01:04

หน้าที่หลักของ I/O Module (5 ข้อ)

  1. Control & timing: ควบคุมการไหลของข้อมูลระหว่างภายในกับอุปกรณ์ภายนอก
  2. Processor communication: ถอดรหัส command, ส่งข้อมูล, รายงาน status, จดจำ address ปลายทาง
  3. Device communication: คุยกับอุปกรณ์ด้วย command
  4. Data buffering: เก็บข้อมูลที่ส่งเข้ามาไว้ก่อน (ถ้า input ก็เอาเข้า memory ถ้า output ก็ส่งออกไปอุปกรณ์)
  5. Error detection: ตรวจจับ error ที่เกิดขึ้นระหว่างส่งผ่าน I/O
ทำไมต้องมี buffer: ความเร็วของ memory เร็วมาก แต่ I/O ช้ากว่ามาก buffer ช่วย balance speed เวลา processing ของ memory ตามไม่ทัน

ไดอะแกรมของ I/O Module

  • Address lines: บอกว่าจะคุยกับ I/O ตัวไหน
  • Control lines: บอกว่า I/O ต้องทำอะไร
  • Data lines / data bus: ชุดข้อมูลที่ส่งผ่าน
  • กลุ่ม Status และ control ต่าง ๆ ที่เกี่ยวข้อง
03:40

เทคนิคการทำ I/O 3 แบบ

  1. Programmed I/O (ง่ายที่สุด): processor ยิงคำสั่งไปให้ I/O แล้ว รอจนกว่า I/O ตอบกลับ จึงได้ข้อมูล คำสั่งไม่ยาก แต่ เสียเวลา processor เพราะต้องนั่งรอ (ไม่มี interrupt)
  2. Interrupt-driven I/O: processor สั่งแล้ว ไปทำงานอื่นต่อได้ เมื่อ I/O พร้อมส่งข้อมูลจึง interrupt กลับมา แล้ว processor ค่อยหันมารับ/ส่งข้อมูล
  3. DMA (Direct Memory Access): I/O กับ main memory แลกเปลี่ยนข้อมูลกันตรง ๆ โดย CPU ไม่ต้องยุ่ง CPU ไปคำนวณงานของตัวเอง
อาจารย์บอกว่า DMA เป็นแบบที่ "นิยมใช้ใน architecture ปัจจุบันมาก" ส่วน flow ฝั่ง CPU ก็ง่ายกว่ากันเยอะ เพราะ CPU ปล่อยให้ตัว DMA จัดการกับ I/O

I/O Commands และ Flowchart ของแต่ละเทคนิค

  • คำสั่ง (command) ของ I/O มี 4 แบบ: Control (บอกให้ทำอะไร), Test (ดู status ก่อน), Read, Write (I/O มีทั้ง input และ output)
  • แบบ Programmed: flowchart เรียงเป็น sequence ไม่ยาก
  • แบบ Interrupt: processor แยกออกมาทำงานของตัวเองได้ และทำงานกับ I/O ก็ต่อเมื่อถูก interrupt
  • แบบ DMA: flow ของ CPU ง่ายสุด เพราะแยกออกจากกัน

Interrupt-driven I/O: สิ่งที่เกิดเมื่อมี Interrupt

  • ทุกครั้งที่เกิด interrupt ต้อง เก็บค่า PC และ status register ไว้ก่อนเริ่มทำงาน (เหมือน flow ที่เคยเรียนใน Ch02)
  • จากนั้น PC ถูกเปลี่ยนเป็นค่าเริ่มต้นของ ISR แล้วเข้าไปรัน
  • เมื่อรัน interrupt เสร็จ return: เอาค่า PC เดิมก่อนกระโดดกลับเข้า PC และ คืนค่าใน stack ทั้งหมด แล้วจึงกลับมาทำงานต่อ
08:48

Device Identification: ระบุว่าใครเป็นคนส่ง Interrupt (4 แบบ)

  1. Multiple interrupt lines: แยกเส้น interrupt คนละเส้น ตรงไปตรงมา ทำให้รู้ทันทีว่าใครเรียก ข้อเสีย: ถ้ามี I/O เยอะ เส้น interrupt ก็เยอะตาม
  2. Software poll: processor กระโดดไปที่ routine ที่ไล่ถาม (poll) ทีละ I/O module ว่าใครเป็นคนเรียก (ใช้เวลานาน)
  3. Daisy chain (hardware poll, vectored): กำหนด priority ว่าใครสำคัญสูง/ต่ำ ส่งสัญญาณ interrupt acknowledge ต่อกันเป็นลูกโซ่
  4. Bus arbitration (vectored): I/O module ต้อง ขอสิทธิ์คุม bus ก่อน จึงจะขอ interrupt ได้ เมื่อได้รับ request แล้ว module จะส่ง address/vector ของ device ผ่านสาย data/address

แนวคิด Pipelining

Hazard ที่ 1: Structural Hazard

  • ปัญหา 3 แบบ: structural hazard, data hazard, control hazard
  • Structural hazard = การใช้ resource ชนกัน (conflict) ในเวลาเดียวกัน
  • วิธีแก้: stall = หยุด pipeline (เกิดช่องว่าง/bubble) จนกว่า resource จะว่าง แล้วจึงทำต่อ
≈15:00

Hazard ที่ 2: Data Hazard และวิธีแก้ (Stall, Forwarding, Code Scheduling)

Data hazard = resource ไม่ได้ชน แต่ ข้อมูลชน/ยังไม่พร้อม

ตัวอย่างบนสไลด์: add x19, x0, x1 ตามด้วย sub x2, x19, x3
sub ต้องใช้ x19 แต่ add ที่อยู่ก่อนหน้ายังไม่ทัน เขียนค่าลง x19 (ยังไม่ถึง write back)
  1. Stall: ง่ายที่สุด แต่ต้องหยุดหลาย cycle ("นักวิจัยบอกว่าไม่ค่อยดี")
  2. Forwarding (Bypassing): สร้าง เส้นทางพิเศษใน datapath ส่งผลลัพธ์จากสถานะ Execute ของคำสั่ง add กลับไปเป็น input ของคำสั่งถัดไปเลย โดยไม่ต้องรอ write back
  3. Code scheduling (จัดเรียงโค้ดใหม่): แก้ที่ assembly หรือ compiler เช่น หลัง load x2 แทนที่จะ add ทันที ให้เอาคำสั่งที่ไม่เกี่ยวข้อง (load x4) มาทำคั่นก่อน วิธีนี้ ไม่ต้องเพิ่ม hardware (bus forward) แต่ไปแก้ที่ compiler/assembler แทน

Hazard ที่ 3: Control Hazard และ Branch Prediction

  • เกิดเมื่อ fetch คำสั่งถัดไปมาแล้ว แต่ คำสั่งก่อนหน้าเป็น branch/jump → กระโดดไปที่อื่น คำสั่งที่ fetch มา ไม่ถูกใช้
  • วิธีแก้ที่ง่ายสุด: ใช้ bubble / stall จนกว่า pipeline จะกลับมาทำงานปกติ
  • แต่ stall ไปเรื่อย ๆ เสียเวลา (waste) จึงมีความพยายามออกแบบ prediction: ใช้ สถิติ/probability เดาว่า branch นี้จะกระโดดจริงไหม
  • ตัวอย่างของอาจารย์: ลูป ที่เช็กเงื่อนไขว่า i เท่ากับ 0 ไหม เมื่อยังลบไม่ถึง 0 ก็ ไม่มีทางกระโดดออกจากลูป จึง fetch คำสั่งถัดไปมาก่อนได้
  • แต่ prediction มีต้นทุนฮาร์ดแวร์สูง ต้องออกแบบวงจรเก็บสถิติเพิ่มใน CPU อาจารย์บอกว่าส่วนใหญ่ นิยมใช้วิธี stall มากกว่า เพราะความซับซ้อนของวงจรทำ prediction มี cost สูงกว่าอยู่ดี
≈20:00

สรุป Pipeline: 3 hazard และ Pipeline Registers

  • สรุป: pipeline ทำงานได้เร็ว ปัญหาที่พบมี 3 type:
    • Structural hazard – ใช้ resource ซ้ำกัน
    • Data hazard – ข้อมูลยังไม่เสร็จ แต่ถูกเรียกใช้
    • Control hazard – เกิด jump/branch ทำให้คำสั่งที่ fetch มาไม่ถูกใช้
  • ทุก stage ของ datapath ต้องมี pipeline registers (ตัวสีฟ้าในรูป) เก็บข้อมูลจาก stage ก่อนหน้า ไม่งั้น ข้อมูลจะถูกคำสั่งถัดไปทับทันที เป็น hardware ที่เพิ่ม (ต้นทุน) แต่ทำให้ CPU ทำงานแบบ pipeline เร็วขึ้นได้

Vector Processor และ Multithreading

  • Vector processor: CPU บางประเภท เช่นตระกูล RISC-V มี version ที่เป็น vector processor มาผสม ส่วนใหญ่ใช้กับคำสั่งคำนวณคณิตศาสตร์เยอะ เช่น คูณ-บวก-คูณ-บวก (multiply–accumulate) ใน digital filter, vector ของภาพ, background subtraction, พีชคณิตเชิงเส้น (ตัวอย่างบนสไลด์: DAXPY)
  • Multithread: ไม่ได้มี hardware เพิ่มจริง แต่ ซอยคำสั่งออกเป็น thread แล้วทำ scheduling processor ตาม thread — ไม่ต้องลงทุนเรื่อง CPU/hardware แต่ได้ลักษณะ parallel ได้เยอะ

Shared Memory vs Distributed Memory

  • Distributed memory (แต่ละ processor มี memory ของตัวเอง): update/sync ข้อมูลระหว่างกัน ทำได้ยาก ต้องมี กระบวนการเพิ่มเติม

  • RAM vs ROM: RAM เป็นแบบ ชั่วคราว (temporal/volatile) ข้อมูลหายได้เมื่อไม่มีไฟ · ROM ถาวรกว่า ปิดไฟแล้วข้อมูลยังอยู่
  • SRAM vs DRAM: SRAM เร็วกว่า · DRAM ช้ากว่า แต่ราคาถูกกว่า

Cache แบบไหน miss น้อยสุด / วิธีเขียนข้อมูลลง Cache

  • เลือกระหว่าง Direct-mapped, Two-way, Fully associative แบบไหนช่วยลด miss ได้ดีที่สุด → Fully associative (miss น้อยที่สุด / hit มากที่สุด)
  • วิธีเขียนข้อมูลลง cache มี Write-through, Write-back และ Write-allocate (อาจารย์ยืนยันว่าถูก)

คำถามที่ 12–13: Bus

16:34

Daisy Chain และตัวตัดสินว่าใครได้ใช้ Bus (Bus Arbitrator)

  • Daisy chain: เกี่ยวกับ priority — ให้ความสำคัญกับตัวที่ priority สูงก่อน แล้วลดหลั่นลงมา
  • เมื่อมี I/O หลายตัวต่ออยู่ที่ bus แล้วขอใช้พร้อมกัน ตัวที่เลือกว่าอุปกรณ์ไหนมีสิทธิ์ใช้ bus เรียกว่า Bus Arbitrator / Arbitration circuit
  • ไม่ใช่ Control Unit และ ไม่ใช่ control line (นักศึกษาเดาผิด 2 ครั้งก่อนได้คำตอบที่ถูก)
